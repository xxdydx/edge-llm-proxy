1. Is the cloud-only-by-default behavior intentional, or a config wiring gap? The default `local_cache_tracking=="off"` makes the whole local-first policy dead unless explicitly enabled — needs confirmation against intent.

7. What is the intended runtime environment for the telemetry sampler (Linux procfs assumed; NVML required) — and is a sampler that dies permanently on exception acceptable?

## Bottom Line

The codebase is architecturally clean and well-factored — the pure-logic modules (router, cost, cloud_cache, trace) are genuinely testable with clean seams — but it ships with **zero tests** for its most bug-prone logic, and the request path carries several real defects: no failover, cloud-only-by-default, unredacted body persistence, unbounded memory/state, and fragile streaming error handling. The highest-leverage next steps are (1) adding unit tests for the pure placement/cache/cost logic, (2) confirming the failover and default-policy intent, and (3) addressing the unredacted-body and unbounded-memory issues.

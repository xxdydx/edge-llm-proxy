# Claude Code collection packet — locked task plan

## Use this packet

Place this directory in the engineering checkout, **outside every experimental repository/container mount**. Paste `START_HERE_SONNET.txt` into Sonnet. It tells Sonnet to read the complete updated master prompt, delegate to Luna, and execute the closed task-harvest procedure before any collection.

The experimental models remain Qwen 27B at the edge and the configured DeepSeek Flash endpoint in the cloud. Sonnet/Luna are engineers, not the repair agents in the dataset. Scope remains A/B/C collection and labelling; no router training or online learning.

## What changed

- Two actual startup IDs are explicit in `SMOKE_TASK_IDS.jsonl`.
- Task sources and their immutable dataset revisions are fixed in `TASK_SOURCE_LOCK.json`.
- Real tasks: 300 training and 60 validation from 8 named SWE-Gym repositories.
- Synthetic tasks: 200 training from 20 named SWE-smith-py repositories; 40 validation from 4 other repositories.
- Complete instance-ID lists are generated by the included deterministic Python selector, **not chosen by Sonnet/Luna**.
- The code supplies split-owned ordered reserves, a preflight gate, staged manifest freezing, and checks against modifying previously frozen assignments.
- The old monolithic SWE-smith task source is replaced by the official Python-specific release.

## What was actually verified here

The official public dataset pages/revisions, source profiles and two startup task IDs were inspected. The selector compiled and all **16 synthetic-metadata tests passed**, including exact quota counts, held-out repository ownership, duplicate/exposure handling, deterministic selection, bounded preflight substitution, and immutability of earlier frozen assignments.

**Not performed:** full source parquet downloads, enumeration of the actual 600-task ID manifest, checking that every selected repository yields its quota after filters, Docker/environment preflight, agent executions, generation of real A/B/C datasets, or an end-to-end test against the user's private project. Network access from the preparation container did not allow full downloads.

The script therefore creates the real literal ID manifests on the user's network-enabled machine and stops on source/supply mismatches. It does not fill gaps with invented IDs. A candidate manifest is still provisional until genuine preflight reports are present. The full benchmark collector must be implemented/adapted by Sonnet/Luna using the master prompt.

## First commands

```bash
python -m unittest discover -s tests -v
python -m pip install -r requirements-task-manifest.txt
python harvest_task_manifest.py fetch --cache .task-source-cache --out task_catalogue_v1
```

Read `TASK_HARVEST_SPEC.md` for the prior-exposure inventory, exact `select` command, preflight-ledger contract and staged `finalise` commands. Do not put the raw parquet or catalogue inside an experimental agent's working directory: source data includes protected test/reference material.
